# PRD — The System Map: an interactive, two-layer map of everything Empire State is built from

> **Linear:** YED-232 · **Date:** 2026-09-27 · **Owner:** Alex · **Status:** approved 2026-09-27, built the same day (PR below)
> · **Appetite:** 3–7d · **Backfilled?** no · **Home:** empire-state-hub, public `/architecture` (replaces v1) · **Mirrors:** ChatPRD (Empire State project) + Notion Project Ideas

**1. Problem & why now.**
The system is now ~30 commands, ~47 skills, 23 agents, 26 hooks, 11 ADRs, a Postgres knowledge graph and a three-seat judge — and the only ways to understand it are a 6,400-word CLAUDE.md, the ADR folder, or a long chat. The v1 `/architecture` page shows counts, four agent groups and two static figures; it says *what exists*, not *why*, *how it was built*, or *what it talks to*. Two consequences are already visible: Alex cannot hold the whole thing in his head between sessions (this session's systems diagnosis had to be re-derived from scratch), and the public surface — the interview artifact — can't show a hiring manager the reasoning behind the build, which is the actual differentiator. Why now: the 2026-09-27 diagnosis found the system "opens well and closes badly" — a served surface (topic intelligence) sat stale for seven weeks because nobody could *see* it was stale. A map with honest status per component is the cheapest fix for that class.
**Press release line:** *Anyone — Alex on Monday morning, or a hiring manager with five minutes — can click any part of the Empire State system and get, in one panel: what it does, why it exists (with the decision it came from), how and when it was built, which tools it uses, what it reads and writes, and what's being built next.* Alex would care; so would the audience the Hub exists for.

**2. Goals / Non-goals.**
Goals: (a) one interactive map of the *whole* system at two zoom levels — **~30 curated components** in six zones, each expandable to its **file-level subgraph** from the ADR-8 system graph; (b) every node and edge is clickable and opens a panel with the six fields above; (c) an **upcoming-build overlay** drawn from `roadmap.md` phases + live Linear, attached to the components each item extends; (d) **status honesty** — every component carries `live | stale | scaffolded | parked | planned`, generated where possible, never flattering; (e) regenerable from repo sources so it does not rot the way `architecture.ts` did (the toolbox-generator lesson).
Non-goals (hard): no live runtime telemetry or metrics on this page (that is `/ops/rigor`); no in-browser editing; no LLM-written prose at build time (generated fields come from frontmatter, ADR titles and git; the *reasoning* is a hand-curated overlay reviewed in the PR); does not replace `/pipeline` (the replay) or `/build-arcs` (the narrative); is **not** YED-126 (the Applied-AI reference-architecture lens over the *market* graph — that maps the industry; this maps *our* system); no ecosystem/`alex`-plugin scope — project-local only, same rule as the toolbox generator.

**3. Solution sketch + alternatives.**
*Data:* `scripts/gen-system-map.mjs` (gen-toolbox pattern) reads the pipeline repo — `.claude/{commands,skills,agents,hooks,scripts}` frontmatter, `docs/adr/*.md`, `.claude/.state/system-graph/{nodes,edges}.jsonl` (325 artifact nodes / 935 `references` edges; rebuilt via `build_graph.py` if absent), `roadmap.md` §3/§5/§6 tables, `git log --diff-filter=A` for first-shipped dates — and merges it with `src/data/system-map.curated.json` (zone, reasoning + its source pointer, edge semantics, status overrides with a reason) → `src/data/system-map.json`. Merge-don't-clobber: curated fields survive regeneration; the run prints added / removed / **stale** (files changed since the overlay's `reviewed_at`). Linear items are fetched at build time with the Hub's existing `@linear/sdk` wiring. `verify-public-safe` runs over the output.
*Render:* React Flow (`@xyflow/react`) + `elkjs` layered layout, custom nodes in the Hub's tokens, zones as swim-lanes, a side panel (bottom sheet on mobile) for the selected node/edge, expand-in-place for layer 2, `?node=` / `?edge=` deep links, and the existing editorial/technical lens toggle (editorial = zone + plain-English summary; technical = files, tools, edge kinds).
*Alternatives rejected:* **(i) hand-drawn SVG/Mermaid figures** (extends v1) — static, no drill-down, rots exactly like the counts did. **(ii) D3 force graph over the raw 325-node ADR-8 graph** — true to the repo but a hairball; nobody learns a system from 935 edges. The two-layer design keeps the honesty of (ii) with the legibility of a curated map. **(iii) Notion/Miro board** — not public, not regenerable, not in the interview artifact. **(iv) Generate the narratives with an LLM at build time** — cheap to write, impossible to trust; reasoning must cite the ADR/note/issue it came from.

**4. Leverage & systems check.**
Leverage point: **#6 information flows** — the map makes "what is stale / half-built / next" visible to the person who decides, which is exactly the missing feedback the 09-27 diagnosis named; direction check: it adds a *reading* surface, not another process rule (Alex declined more rules that day). Archetypes guarded: **Shifting the Burden** — the overlay must be part of the build path (the PR that adds a component adds its map entry; `npm run check` fails on components with no overlay entry), not an optional doc; **Seeking the Wrong Goal** — a beautiful map of a flattering system is worse than none, so status is generated-first and every curated claim carries a pointer.

**5. Rabbit holes + pre-mortem.**
Rabbit holes: graph layout tuning (fix: elk layered + zone lanes, no force sim, stop when readable); "every file should be a curated node" (fix: ~30 hard cap on layer 1, the rest is layer 2); animating edges/flows (fix: none in v1). Pre-mortem — *it's six weeks later and this was a regret because…* **(1) the overlay rotted** → the generator's stale list is printed on every run and rendered as a badge; `verify-public-safe` fails on unknown component ids. **(2) it's a hairball on a phone** → layer 1 ≤ 35 nodes, zones collapsible, layer 2 lazy, panel as bottom sheet, tested at 390px. **(3) it says something untrue in public** → status is machine-derived where it can be (file exists / last commit / roadmap state / Linear state), overrides need a reason, and the judge grades the overlay for confidence-honesty (rubric cap ≤0.65 applies). **(4) file paths leak something private** → layer 2 is built only from the ADR-8 graph, which already excludes gitignored/personal files; `verify-public-safe` extended to the JSON.

**6. Success criteria + eval.**
North-star (leading): **time-to-answer** — Alex or a reader can answer "what does X do, why does it exist, what's next for it" for any component in <60s from the page, measured by a 5-question self-test at the DoD close and repeated at `/rigor-review`. Guardrail: **0 status contradictions** — no component whose rendered status disagrees with reality at review (the metric the topic-intelligence incident would have tripped). Value-action-registry row: `{stale-overlay count > 0 at generation → build warning + badge on the node → in-session DoD}`; `{status contradiction found at rigor-review → fix the generator rule, not the JSON → weekly review}`.
Acceptance criteria (judge-gradable): **AC1** `/architecture` renders the React Flow map with ≥25 and ≤35 curated components across the six zones (Intake · Pipelines · Knowledge graph · Systems of record · Rigor layer · Surfaces); v1 page code removed. **AC2** Selecting any node opens a panel with all six fields: what it does (generated), why it exists (curated, with a source pointer), build story (first-shipped date + Linear/ADR refs), tools used (generated from `tools:` frontmatter + MCP references), interactions (its edges, listed), files (count + expand). **AC3** Selecting any edge opens a panel with kind ∈ {reads, writes, dispatches, gates, produces, consumes, depends-on} + summary. **AC4** Every component expands to its file-level subgraph sourced from the ADR-8 nodes/edges; file nodes show frontmatter description + referencing files. **AC5** Build-path overlay: roadmap phases P1–P3 + anchors A1–A3 with dates + live Linear (Todo/In Progress/Backlog ≥ Medium), rendered dashed and attached to the components they extend. **AC6** Every component carries a status; the known cases render truthfully (topic-intelligence = stale/YED-230; workflows scaffolded vs wired per WORKFLOWS.md). *Amended 2026-09-27:* removed/disabled tools (Gamma, Granola) are not components of the system and are recorded in the why-text of the component that replaced them, not as nodes. **AC7** `npm run gen:system-map` regenerates from sources, preserves curated fields, prints added/removed/stale; `npm run check` passes. **AC8** `?node=` / `?edge=` deep links restore selection; usable at 390px. **AC9** Layer 1 first render < 1.5s desktop; layer 2 loads on expand.

**7. AI-native fields.** Human–AI boundary: the generator derives facts; Claude drafts the curated overlay in the PR; Alex approves it (the reasoning is his system's story). Failure UX: an unknown/unmapped file falls into an "unmapped" bucket rendered visibly, never dropped. Built for the slope: nothing model-dependent at runtime. Living acceptance layer: the build-quality judge on the overlay + this PRD's ACs; `/rigor-review` re-checks status honesty.

**8. Build-time details — deferred, not committed.** Exact node count and zone membership; elk vs dagre; whether layer 2 renders inside the same canvas or a nested canvas; Linear fetch at build (ISR) vs a checked-in snapshot refreshed by the generator; the curated JSON schema (zod, like the rest of `src/data`); keeping or retiring the v1 figure registry entries.

**9. Constitution / invariants.** ADR-8 (the system graph is derived, gitignored, rebuilt — never hand-edited); ADR-9 (no PII: no email/phone/bio in any node); build-in-public policy + `verify-public-safe`; the toolbox-generator spec's merge-don't-clobber rule and project-local scope; SDK constraint (the map must show fan-out in the parent thread correctly); Linear as the source of truth for "what's open" (the build path reads it, never restates it).
